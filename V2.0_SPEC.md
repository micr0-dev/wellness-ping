# Wellness-Ping v2.0 — Feature Spec

Built from the full original thread (55 messages, 54 replies) + GitHub issues + operational incidents.

## Priority Tiers

- **P0 (must, core identity):** Duress PIN, PIN check-in, travel pause + auto-reenable, customizable messages
- **P1 (the "etc."):** Signal channel, HTML emails, fresh-link-per-check-in
- **P2 (harder/security):** Signed anti-replay PONGs, multi-provider email failover, TOTP, high-security tier

---

## A. Safety & Security (highest priority)

### 1. Duress PIN
**Source:** Original thread — you explicitly said you'd add it

If you're forced to check in, entering your duress PIN silently alerts your contacts immediately (instead of confirming OK).

**Implementation:**
- Add `duress_pin` field to User struct
- When `/pong` receives duress PIN instead of normal token, trigger alert without user knowing
- Optional: Show fake "OK" page to observer

### 2. PIN-based check-in
**Source:** Thread (@micr0: "I was gonna add a pin in the next version")

Optional manual check-in via PIN instead of only the emailed link (for stronger security tier).

**Implementation:**
- Add `/pin-checkin` endpoint accepting email + PIN
- Users can set a PIN in settings
- Works without email round-trip

### 3. Signed PONGs / anti-replay verification
**Source:** Thread (@datenwolf)

Cryptographically sign check-in responses (PBKDF/asymmetric) with a randomized token so a stolen email/phone can't fake "I'm OK".

**Implementation:**
- Generate signed tokens with timestamps
- Validate signature on `/pong`
- Prevent replay attacks with nonce tracking

### 4. Biometric / high-security tier
**Source:** Thread (@jaybird110127)

Optional harder verification for people in genuinely dangerous situations (activists, DV survivors, at-risk people).

**Implementation:**
- Add `security_tier` field (basic, high)
- High tier requires additional verification steps
- Longer session timeouts, stricter token validation

## B. Scheduling & Usability (most-requested theme)

### 5. Vacation / travel pause
**Source:** Thread (@suramya)

Disable checks for a set period when you have no connectivity, so your contacts don't panic.

**Implementation:**
- Add `paused_until` field to User
- Skip ping checks if `time.Now() < paused_until`
- Settings UI to set pause duration

### 6. Scheduled pause with auto-reenable
**Source:** Thread (@suramya) (you said "I'll add this to my list!")

"I'm out for 2 weeks" → checks off for 2 weeks, then auto-resume with no manual step.

**Implementation:**
- Same as #5, but auto-resume when `paused_until` expires
- Send reminder before pause expires

### 7. Fresh link per check-in
**Source:** GitHub issue #3 (already partially done)

New URL each ping (fixes browser-cache/stale-link issue).

**Implementation:**
- Generate new token on each `/pong` click
- Already done in `pingScheduler()` — verify it's working

## C. Notification Channels (the "etc." — biggest expansion)

### 8. Signal bot support
**Source:** You + thread context

Check-in + alerts via Signal (your idea); crucial because **email can be the weakest link** (provider outage, spam, takeover).

**Implementation:**
- Add Signal integration via Signal-CLI or SignalR
- Store Signal phone number in User
- Send alerts to Signal in addition to email

### 9. Additional messenger channels
**Source:** Thread (@viq, @jaybird110127)

Matrix, Telegram, WhatsApp, SMS — so it works even if your phone is off/confiscated (the "device-independent" angle).

**Implementation:**
- Abstract notification channel interface
- Add Telegram bot support
- Add Matrix bot support
- SMS fallback via Twilio/other provider

### 10. HTML email formatting
**Source:** GitHub issue #5

Hyperlink the alert URL so it works in all email clients.

**Implementation:**
- Already using `HtmlBody` in Postmark calls
- Ensure links are clickable `<a href="...">`

## D. Customization

### 11. Custom alert & all-clear message content
**Source:** GitHub issue #6

Your contacts get the words *you* want them to read.

**Implementation:**
- Add `alert_message` and `all_clear_message` fields to User
- Use these in `sendAlert()` and `sendAllClearEmail()`
- Default to current hardcoded messages

## E. Ops robustness & sustainability

### 12. Signup/verification spam protection
**Source:** Your Apr 17, 2026 post

Someone abused your signup form to spam verification emails.

**Implementation:**
- Rate limiting per IP/email
- Turnstile already in place — verify it's working
- Add CAPTCHA to `/send-code`

### 13. Email-provider resilience
**Source:** Your Apr 17, 2026 post

Postmark cut service with no notice → outage. Support **multiple/self-hosted outbound providers** (failover) so it never dies with one vendor.

**Implementation:**
- Abstract email provider interface
- Support SendGrid, Mailgun, SMTP as fallbacks
- Failover logic when primary fails

### 14. TOTP / ping-in-advance
**Source:** GitHub issue #4

Authenticate and ping early to skip an email round-trip (also cuts provider cost).

**Implementation:**
- Generate TOTP secret for users
- Allow check-in via TOTP code (no email needed)
- Works offline on user's device

### 15. Foundation / not single-point-of-failure
**Source:** Thread (@sven222)

Move to a foundation/governance so it survives any one person.

**Implementation:**
- Document governance model
- Add multi-sig deployment process
- Open infrastructure access to maintainers
