# Wellness-Ping v2.0 — Feature Spec

Built from the full original thread (55 messages, 54 replies) + GitHub issues + operational incidents.

## Priority Tiers

- **P0 (must, core identity):** Duress PIN, vacation pause + auto-reenable, customizable messages, 2FA
- **P1 (the "etc."):** Signal channel, HTML emails, fresh-link-per-check-in
- **P2 (harder/security):** Signed anti-replay PONGs, multi-provider email failover, Passkeys

---

## A. Safety & Security (highest priority)

### 1. Duress PIN
**Source:** Original thread

If you're forced to check in, entering your duress PIN silently alerts your contacts immediately (instead of confirming OK).

**Implementation:**
- Add `duress_pin` field to User struct
- When `/pong` receives duress PIN, trigger alert without user knowing
- Show fake "OK" page to observer

### 2. 2FA with Authenticator App
**Source:** Community request for enhanced security

Require a TOTP code from an authenticator app to check in.

**Implementation:**
- Add `totp_secret` and `require_totp` fields to User
- Generate TOTP secret when user enables 2FA
- Validate TOTP code on `/pong` endpoint
- TOTP required in addition to token (not replacement)

---

## B. Scheduling & Usability (most-requested theme)

### 3. Vacation / Travel Pause
**Source:** Thread (@suramya)

Disable checks for a set period when you have no connectivity, so your contacts don't panic.

**Implementation:**
- Add `paused_until` field to User
- Skip ping checks if `time.Now() < paused_until`
- Auto-resume when pause expires
- Settings UI to set pause duration

---

## C. Notification Channels (the "etc." — biggest expansion)

### 4. Signal bot support
**Source:** You + thread context

Check-in + alerts via Signal (your idea); crucial because **email can be the weakest link** (provider outage, spam, takeover).

**Implementation:**
- Add Signal integration via Signal-CLI or SignalR
- Store Signal phone number in User
- Send alerts to Signal in addition to email

### 5. HTML email formatting
**Source:** GitHub issue #5

Hyperlink the alert URL so it works in all email clients.

**Implementation:**
- Already using `HtmlBody` in Postmark calls
- Ensure links are clickable `<a href="...">`

---

## D. Customization

### 6. Custom alert & all-clear message content
**Source:** GitHub issue #6

Your contacts get the words *you* want them to read.

**Implementation:**
- Add `alert_message` and `all_clear_message` fields to User
- Use these in `sendAlert()` and `sendAllClearEmail()`
- Default to current hardcoded messages

---

## E. Ops robustness & sustainability

### 7. Signup/verification spam protection
**Source:** Your Apr 17, 2026 post

Someone abused your signup form to spam verification emails.

**Implementation:**
- Rate limiting per IP/email
- Turnstile already in place — verify it's working
- Add CAPTCHA to `/send-code`

### 8. Email-provider resilience
**Source:** Your Apr 17, 2026 post

Postmark cut service with no notice → outage. Support **multiple/self-hosted outbound providers** (failover) so it never dies with one vendor.

**Implementation:**
- Abstract email provider interface
- Support SendGrid, Mailgun, SMTP as fallbacks
- Failover logic when primary fails

### 9. Foundation / not single-point-of-failure
**Source:** Thread (@sven222)

Move to a foundation/governance so it survives any one person.

**Implementation:**
- Document governance model
- Add multi-sig deployment process
- Open infrastructure access to maintainers
